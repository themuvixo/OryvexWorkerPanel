Get a build

Every release on GitHub ships three files:

  • worker-single-file.jsCloudflare Workers, paste into the editor.
  • oryvex-worker-panel-pages.zipCloudflare Pages, upload as assets.
  • SHA256SUMS.txtChecksums for both.

Download v{{VERSION}}

Forked the repo? Push to main and the Release workflow builds, tags and publishes your own release. See Updates & releases.

Cloudflare Workers Recommended

  1. Create a KV namespaceStorage & Databases → KV → Create, e.g. oryvex-kv.
  2. Create the WorkerWorkers & Pages → Create → Start with Hello World → Deploy → Edit code. Replace everything with worker-single-file.js and deploy.
  3. Bind KVSettings → Bindings → Add → KV namespace, variable name exactly KV.
  4. Open the Worker URLSet your admin password. Done.

Skipped step 3? The Worker shows an E_KV_MISSING page with these steps, and tells you if KV was bound under a different name.

Cloudflare Pages

  1. UploadWorkers & Pages → Create → Pages → Upload assets, then upload oryvex-worker-panel-pages.zip.
  2. ConfigureIn Settings → Functions set compatibility date 2024-09-23 or later and bind KV as KV.
  3. RedeployUpload the same zip again so the binding applies.

Wrangler (CLI)

npm ci
npx wrangler kv namespace create KV   # put the id in wrangler.toml
npm run deploy

Set ORYVEX_UPDATE_REPO=owner/repo before building locally so the in-panel updater knows where to look.

Build locally

npm ci
pip install fonttools brotli   # optional, smaller fonts
npm run build                  # worker-single-file.js + pages zip
npm test                       # unit tests
npm run build:site             # this docs site into _site/

panel-preview.html opens the whole panel offline with demo data.
